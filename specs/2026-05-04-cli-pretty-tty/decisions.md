# Decisions Log — Pretty TTY Output (cli-pretty-tty)

All decisions made during Phase 1 + Phase 2. Locked unless noted.

## Phase 1 — Discovery decisions

| # | Decision | Rationale | Source |
|---|---|---|---|
| D-1 | `--pretty` repurposed: now means "human-readable colored multi-line" (the new mode); the old `serde_json::to_string_pretty` (indented JSON) branch is removed. | Old `--pretty` was indented JSON, which has no real machine consumer (canonical JSON is the script path). Repurposing keeps flag count down and matches AC-TTY-03 wording. | Step 3 Q1 |
| D-2 | Tailored multi-line layouts for every receipt-emitting subcommand (~15 commands). Schema-driven `PrettyRenderer` becomes the safety-net fallback for any method without a tailored renderer (and for receipts that fail to deserialize). | Best UX consistency. User accepted size bump S → M to fund this. | Step 3 Q2 |
| D-3 | `--quiet` Phase 1 base: `loom session create --quiet` prints session_id; `loom action ... --quiet` prints action_hash. Errors always to stderr. | Mirrors AC-TTY-03 + standard shell pipeline pattern. | Step 3 Q3 |
| D-4 | Hand-rolled ANSI helper (no new workspace dep). | Surface is ≤6 ANSI codes (RESET, BOLD, DIM, RED, GREEN, YELLOW, CYAN). Avoids deny.toml round-trips. Anstyle (transitive via clap) was the runner-up. | Step 3 Q4 |
| D-5 | Three carve-outs are NOT touched by TTY/--pretty/--json: `--version` (SR-CLI-01 latency), `serve` HELLO_TOKEN line (daemon handshake), `session export` binary bytes. `doctor` will be migrated through the new formatter. | These three have non-receipt or latency-bound contracts; rerouting risks breaking SR-CLI-01 (≤200ms version) and the daemon handshake. | Phase 1 scan |
| D-6 | Use `std::io::IsTerminal` from stdlib (no new dep, MSRV 1.92 ≥ 1.70). | Confirmed by research notes; `atty` is officially deprecated. | Step 4 research |

## Phase 2 — Council intake decisions

| # | Decision | Rationale | Source |
|---|---|---|---|
| D-7 | **Flag precedence: `--quiet` > `--json` > `--pretty` > TTY auto-detect.** If both `--json` and `--pretty` are passed without `--quiet`, exit 2 with `Usage` ("conflicting output flags"). `--quiet` may compose with `--json` (machine pipeline wants id-only stdout) or `--pretty` (human wants id-only at TTY) — both yield id-only output. | Quietest/most-specific wins. Mutual exclusion of --json/--pretty avoids silent override surprise; docker, gh have similar policies. | Step 5 council Q1 (P&UX) |
| D-8 | **Universal --quiet rule** for all 15+ subcommands: <br>• single-resource creators/operators (`session create/close/abort/replay/export/validate`, `action`, `vault add`) → print canonical id on stdout, ONE line. <br>• list (`session list`, `vault list`) → newline-separated ids. <br>• no-primary-id (`gc`, `doctor`, `postinstall`, `serve`) → silent on stdout. <br>• errors always to stderr. <br>Each command's `--help` documents its --quiet output. | Mirrors gh/kubectl. Generalises Phase 1's narrow rule into a complete, predictable policy. Every command now has a `--quiet` contract a user can grep for. | Step 5 council Q3 (P&UX) |
| D-9 | **"More details" tail block** in pretty mode: the curated renderer renders curated fields, then appends a dim-rendered (`DIM`-coded) section: any receipt fields NOT in the curated set, in JSON-Schema property order, as `key: value` lines under a faint `── more ──` separator. If receipt has zero unrendered fields, the separator + section is suppressed. | Curated layouts can never silently hide info added by the daemon. Aligns with the existing PrettyRenderer pattern (schema-driven property order). Cost is ~30 LOC + a golden test per command. | Step 5 council Q4 (P&UX) |
| D-10 | **Error formatting**: status quo preserved. Action error path: JSON receipt on stdout (SR-CLI-03 / byte-exact AC-TTY-02), prose on stderr via `error_mapper::print_error`. At TTY, colorize the stderr prose red+bold. Under `--json`, stderr prose stays plain (matches today's bytes). Under `--pretty`, stderr prose colored. Under `--quiet`, stderr prose still emitted (errors are never suppressed). | Smallest contract change. Avoids inventing a new stderr-JSON contract. JSON receipt on stdout is enough for machines. | Step 5 council Q5 (P&UX) + Q4 (Devil) |

## Phase 2 — Defaults & deferrals (worth-considering questions, not asked)

These were raised by the council. Defaulting per recommendation, documenting; user can override with a follow-up.

| # | Default | Rationale | Source |
|---|---|---|---|
| D-11 | **Terminal width**: fixed-width layouts designed to fit 80 cols. No responsive narrowing in v1. Field labels and known values fit; long URLs (`final_url`) wrap with continuation indent at 76 cols. | Responsive layout adds complexity. 80-col is a universal-floor that handles split panes. Follow-up issue can add `term_size`-aware compact mode later. | Step 5 council Q2 (P&UX) |
| D-12 | **No banners/spinners/progress indicators** introduced in this PR. Pretty receipt projection goes on stdout (replaces canonical JSON when at TTY). Errors on stderr. | We're not adding interactive UX in this scope. Council Q1 (Tech) is about future progress indicators — defer until they exist. | Step 5 council Q1 (Tech) |
| D-13 | **No `--pretty` deprecation warning**. The old `--pretty` users got indented JSON; they will now get colored prose. CHANGELOG entry under "Breaking" calls this out. No transitional `--pretty-json` alias. | Adding a one-time stderr warning would create test pollution and require state-tracking that's out of proportion to the breakage surface (almost nobody runs `--pretty` non-interactively for indented JSON). | Step 5 council Q3 (Tech), Q5 (Devil) |
| D-14 | **No streaming output for large list receipts**. Implementation builds the full pretty string in memory, then writes once. The receipt is already fully in memory after RPC return — streaming would have to interleave with serde_json deserialization, which is a much larger refactor. | If a real perf issue surfaces (e.g. session list with >5k sessions), follow-up adds streaming. Benchmarks added in Phase 3 will catch regressions vs. canonical JSON. | Step 5 council Q4 (Tech), Q3 (Devil) |
| D-15 | **Windows scope**: tested on macOS + Linux (CI). Windows ConPTY is handled by `std::io::IsTerminal` natively. Legacy non-ANSI Windows consoles may show raw escape codes if `NO_COLOR` is unset; documented in CHANGELOG. No special Windows code path in this PR. | Hand-rolled ANSI is fine on modern Windows (Win10 1809+ has ConPTY). Legacy console support is a follow-up; users can set `NO_COLOR=1`. | Step 5 council Q2 (Devil) |
| D-16 | **NO_COLOR spec correctness fix**: existing `pretty_renderer::detect_color_enabled` uses `std::env::var("NO_COLOR").is_ok()`, which treats `NO_COLOR=""` (empty) as a disable signal. The no-color.org spec requires the variable to be **non-empty**. Fix is in scope: change to `var("NO_COLOR").map(|s| !s.is_empty()).unwrap_or(false)`. Add interface test. | Bug discovered during Step 4 research. Cheap to fix; otherwise CI environments that set `NO_COLOR=` for parent processes would unintentionally disable color. | Step 4 research |
| D-17 | **`--no-color` CLI flag**: added as global flag (mirrors NO_COLOR env). Precedence: `--no-color` > `NO_COLOR` env > `TERM=dumb` > TTY auto-detect. CHANGELOG: AC-TTY-04 satisfied. | Required by AC-TTY-04. Aligns with anstyle/clap convention. | AC-TTY-04 |

## Decisions affecting the scan / build plan

- All 21 stdout call sites now route through a single new entry point (working name `output::emit(receipt, command_id, cfg)`), which:
  1. Reads `cfg.output_mode` (resolved by precedence rules above).
  2. Dispatches to: `quiet` (id only), `json` (canonical JSON), `pretty_curated` (per-command renderer), or `pretty_fallback` (existing PrettyRenderer + tail block).
  3. Returns bytes; caller writes via `OutputSink`.
- The carve-outs (`--version`, `serve` HELLO, `session export` bytes) bypass `output::emit` and write directly.
- Errors continue through `error_mapper::print_error` to stderr, with new color path at TTY/--pretty.

## Phase 2 — Plan-review revisions (Gemini cross-model + GLM-4.7 ambiguity)

| # | Decision | Rationale | Source |
|---|---|---|---|
| D-18 | **Tail block sensitive-field redaction**: before printing a key in the "more details" tail, lower-case-match the key name against a conservative denylist regex `(?i)(token|secret|password|api_?key|bearer|credential|cookie|jwt|session_?key)`. Match → render `<key>: <redacted>` (DIM red). Same redaction also applied to fallback `PrettyRenderer`. | The tail block surfaces every receipt field, including ones the daemon adds in future. Without redaction, a future receipt field named `auth_token` would silently print to a developer's screen. The `--json` path is unchanged: machines see the raw value (consistent with today's contract). The redaction is a defense-in-depth visual shield, not an authorization control. | Gemini G1 |
| D-19 | **`quiet_id` is per-renderer**, not a centralized match. The `CuratedRenderer` trait gets `fn quiet_id(&self, value: &serde_json::Value) -> Option<String>` with a default impl returning `None`. Each renderer overrides as appropriate (e.g. `SessionCreate::quiet_id` returns `value["session_id"].as_str()`; `WebGenericAction::quiet_id` returns `value["action_hash"].as_str()`). For methods with no curated renderer, `--quiet` falls back to silent (None). | Decentralizes the brittle method-name match. New renderers ship with their own `--quiet` contract. Easier to audit + harder to drift. | Gemini G2 |
| D-20 | **Two color flags**: `cfg.stdout_color_enabled` and `cfg.stderr_color_enabled`. Each resolved independently per its stream's TTY status + env vars. Curated renderer reads `stdout_color_enabled`; `error_mapper::print_error` reads `stderr_color_enabled`. | Stdout being a pipe doesn't mean stderr is — common case: `loom action ... > out.json` keeps stderr a TTY, so error prose can still be colored. | Gemini G3 |
| D-21 | **Empty-state copy** for list commands at TTY: `session list` empty → `<DIM>No sessions found.</DIM>\n`; `vault list` empty → `<DIM>No vault entries.</DIM>\n`. At non-TTY (`--json` mode), receipts emit empty arrays canonically (e.g. `[]` or `{"sessions":[]}`) — byte-exact AC-TTY-02 preserved. | Empty list with just a header is poor UX. Empty arrays in JSON are well-defined for machines. | Gemini G4 |
| D-22 | **Color resolution adds CLICOLOR conventions and `--color=auto\|always\|never` flag.** Replace single `--no-color` with `--color=<choice>` (default `auto`). `--no-color` becomes a clap-level alias for `--color=never`. Per-stream resolution (D-20) precedence: `--color=always` → enabled. Else `--color=never` → disabled. Else `CLICOLOR_FORCE` (non-empty) → enabled regardless of TTY. Else `NO_COLOR` (non-empty per D-16) → disabled. Else `CLICOLOR=0` → disabled. Else `TERM=dumb` → disabled. Else `IsTerminal(stream)` decides. | Aligns with anstyle/clap convention and the broader CLI ecosystem. `--color=always` is the standard escape hatch for forcing color into pipes (e.g. `cmd --color=always | less -R`). `CLICOLOR_FORCE` matches BSD/GNU grep convention. | Gemini G5 |
| D-23 | **`CuratedRenderer` returns dynamic consumed key set**. Trait: `fn render(&self, value: &serde_json::Value, cfg: &CliConfig) -> Result<RenderedReceipt, CliError>` where `RenderedReceipt { text: String, consumed_keys: HashSet<String> }`. The dispatcher computes `tail_keys = receipt_keys ∖ consumed_keys` and renders the tail block. Also: if `render` returns `Err`, dispatcher falls back to `PrettyFallback` (`PrettyRenderer::render`) and emits a single stderr warning (`curated render failed for <method>: <err>; degraded to fallback`). | Lets a renderer dynamically omit keys (e.g. when a value is null and the renderer chose not to print it) without lying via a static `rendered_keys`. The Err-fallback path makes failure observable instead of crashing. | Gemini G6, Ambiguity A4 |
| D-24 | **Tail block deterministic order**: when SchemaCache has the response schema, tail keys appear in JSON-Schema property order. Otherwise, sort alphabetically (NOT `HashMap` iteration order — that's randomised per process and would break golden tests). Documented in the renderer module. | Caught by ambiguity scan. Golden-file tests need byte-exact reproducibility. | Ambiguity A1 |
| D-25 | **`emit()` callsite error handling**: `emit` returns `Result<String, CliError>`. All 18 callsites use `?` to propagate as a normal `CliError`. The error case is reached only on canonical-JSON serialisation failure (already a `CliError::Internal` today) or on `--quiet` id-extraction failure when the receipt is malformed (also `CliError::Internal`). No `unwrap`/`expect`. | Caught by ambiguity scan. Consistent with existing handler patterns (every handler is `Result<(), CliError>` and propagates with `?`). | Ambiguity A5 |
| D-26 | **`session list` table column widths**: id=26 chars (ULID is 26), status=10 chars, created_at=20 chars (RFC3339 truncated to seconds, e.g. `2026-05-04T14:21:24Z`). Total = 56 + 2 separator chars = 58 chars, well within 80-col floor. Long values truncate with `…` (single Unicode ellipsis) at the column boundary. Header row dim. Blank line separates header from rows; no other vertical padding. | Caught by ambiguity scan. Defines the layout precisely so any implementer produces the same bytes. | Ambiguity A2 |
| D-27 | **`session diff` per-diff line format**: `<RED>- key: old_value</RED>` followed by `<GREEN>+ key: new_value</GREEN>`. Indented two spaces. Values JSON-stringified inline (truncate >80 chars with `…`). Mirrors unified-diff convention and matches `git diff` mental model. | Caught by ambiguity scan. Reduces guesswork. | Ambiguity A3 |
| D-28 | **Pluralization helper**: small inline helper `fn plural(n: u64, singular: &str) -> String` returning `format!("{} {}", n, if n == 1 { singular.to_string() } else { format!("{}s", singular) })`. Used by `web.navigate` for `request(s)`, `error(s)`, `byte(s)`. Doesn't pluralize "bytes" (unit, not countable). Format: `network_summary: <plural(total, "request")>, <bytes_human> bytes, <plural(error_count, "error")>`. | Caught by ambiguity scan. Avoids "1 errors". | Ambiguity A6 |

| # | Decision | Rationale | Source |

| D-29 | **Recursive sensitive-field redaction**, applied uniformly to curated, tail, AND fallback paths (NOT just tail). The redaction walker recurses into nested objects and arrays. | D-30 | **Curated renderer module is a directory, not a single file**: `loom-cli/src/pretty_renderer/curated/` containing `mod.rs` (registry + dispatcher), `session_create.rs`, `session_list.rs`, `session_inspect.rs`, `session_diff.rs`, `session_close.rs`, `session_abort.rs`, `session_replay.rs`, `session_validate.rs`, `web_navigate.rs`, `web_generic_action.rs`, `web_evaluate.rs`, `vault_add.rs`, `vault_list.rs`, `vault_grant_revoke.rs`, `gc.rs`, `doctor.rs`, `import_playwright.rs`, `benchmark.rs`. | D-32 | **Curated-renderer fallback warning is rate-limited** to once per method per process. Implemented via `static WARNED: OnceLock<Mutex<HashSet<&'static str>>>`. Rate-limit makes the first failure visible while not poisoning long-running scripts. | Council devil |
| D-33 | **Additional tests** (in `loom-cli/tests/`): <br>• `integration_tail_determinism::tail_order_byte_exact_under_no_schema` — render same receipt 100 times, assert identical bytes. <br>• `integration_malformed_receipts::*` — fuzz-style: missing required fields, wrong types, deeply-nested null, truncated arrays. Devil reviewer (method-name validation, lighter version). | Council test_engineer + devil |
| D-34 | **Golden-file tests scoped to happy paths only**: 5 fixtures (`session_create_at_tty.txt`, `web_navigate_at_tty.txt`, `gc_at_tty.txt`, `doctor_at_tty.txt`, `error_red_at_tty.txt`).
